# 《见仙·山门》从文字联玩到视频试产

## 当前能交给机器什么

六幕正文和带稳定节点编号的剧情图，可用于抽取资产候选、生成分镜草案、排临时对白、做静帧联玩。现行图有 500 个场景节点、39 个选择节点、48 个终点；场景内共有 1849 条画面段落记录，按完整段落内容精确去重为 187 种。相同文本仍可能需要不同伤势或道具状态，同一段又常有多个机位。不能据此直接报价或逐条生成视频。

仓库已有影视交付规格候选、成片哈希清单设计及 Windows 播放验证计划。可见仓库中未找到批准的人设参考图、场景多机位图、实物道具图、对白音频、可执行视频生成工作流或成片。外部盘和付费平台账户未盘点。以下是试产建议，未跑模型或验证时延。

## 开源项目提供哪一段

| 项目 | 从项目文档核对的能力 | 接到《见仙》的方式 |
| --- | --- | --- |
| Toonflow | 管理角色与场景资产，在分镜中引用资产，支持 3D 预演、逐镜生成与剪辑 | 最接近美术和导演工作台。用同一套四人、一扇窗口试正反打，先验资产版本与产物能否导出，再定是否采用其界面。[项目文档](https://github.com/HBAI-Ltd/Toonflow-app/blob/master/docs/readme/readmeEn.md) |
| OpenMontage | Backlot 以磁盘项目为依据呈现各场候选、提示、成本和审核 | 适合 Codex 驱动的单场试制；输入已选定的镜头，导出多个片段交剧情图引用。选项时机、视角和分支合流由本项目决定。[官方架构](https://github.com/OpenMontageInc/OpenMontage/blob/main/docs/ARCHITECTURE.md) · [项目与 Backlot](https://github.com/OpenMontageInc/OpenMontage) |
| ComfyUI | 工作流提交后返回任务 ID，可查执行队列、历史及输出 | 作为本地执行端。把输入参考图、工作流、模型版本与输出镜号绑定。超时先查任务状态，避免重复提交付费或长耗时镜头。[服务 API](https://docs.comfy.org/development/comfyui-server/comms_routes) |
| Wan2.2、MuseTalk | 前者有图像驱动的视频生成，TI2V-5B 官方 720P 示例列出至少 24GB 显存；后者用音频驱动脸部口型，官方列有唇形和身份细节保真局限 | 4080 本地先测分镜、短镜与口型。相同参考图、台词同时作为国内付费 API 的对照输入。记录每条合格秒的时间与费用，当前无本机速度或适配保证。[Wan](https://github.com/Wan-Video/Wan2.2) · [MuseTalk](https://github.com/TMElyralab/MuseTalk) |

建议先选一套上层工作台。以个人制作、主要用 Codex 推进为前提，先试 OpenMontage 编排一个场景；需要亲手排站位时再对比 Toonflow。两者并行成为资产主库会多出一轮人工对账。

## 生产缺口与优先级

| 优先 | 缺口 | 应交付的最小输入和判断方法 |
| --- | --- | --- |
| P0 | 美术方向及角色身份 | 先定一张四人同框的真人影视风格样张。每个主要角色有正、侧、四分之三脸和全身比例、身高对照、发式、衣料、鞋袖、惯用手、表情、声音样句。服装与伤势分版本：周野桥前／右臂伤后，裴照雪右腕缠布／左手执剑，陆寻灰衣／外门袍。逆光或换角度仍认得人。 |
| P0 | 环境空间与陈设 | 丹房窗内外主视图、俯视草图、两侧反打、柜台高度、光源与群演区；青崖给桥两岸、左右阶、闸、药车、水槽一张方位图。固定建筑、灯架、货架可并进环境底图；会被拿走、遮挡人物、跨镜改变状态的物件单独建档。 |
| P0 | 道具、服饰标记和法术 | 每件关键物设资产号、相对手掌的尺寸、材质、正反图、数量、归属人及前后状态。青瓷瓶需封口／开封／剩大半，工分牌需辨别持有人；瓶签三纹与赤纹芝对应。灰符、瞳纹内芯、剑气第一与第二道分别定轮廓、亮灭节拍和声音。瓶签与木牌数字可作为后期图层。 |
| P0 | 分镜、表演和分支状态 | 每个镜头写谁在看、景别、机位、屏幕方向、开闭帧、对白区间及一项主要动作。每个剧情入口明确伤势、衣着、道具和谁知道秘密。相同节点变体先核对画面与声音，再绑定共用片段或替换镜头。 |
| P0 | 声音及剪辑时间线 | 四人音色样句、重音和停顿、逐句音轨、环境底声、动作音、配乐分轨、字幕。先录临时对白排时长；能听清“等了三个月”之后再切夺瓶。无对白、背面、反应镜可绕开多人口型。 |
| P1 | 批处理、审核与局部重做 | 保存镜头号、版本、引用资产版本、工作流与模型标识、参数、输入哈希、任务 ID、候选和选用版本；记录失败原因、耗时、费用。只让依赖变更素材的镜头失效，保留已选版本直至替代品审核通过。相同 seed 不能单独保证同脸或跨平台复现。 |
| P1 | 成片入库与游戏播放 | 映射剧情节点→有序片段→音轨字幕。保存校验和、画幅、帧率、响度、时长、片头尾状态；分支接点检验视线、持物、光线、声音尾巴和选项遮挡。Windows 打包离线测切支、回退和存档；留模型、素材、音色及配乐来源记录。 |

## 第一包只做丹房窗口

生产目标暂定 25–40 秒，覆盖陆寻收药、严承索药被拒、当面夺药。暂定四个出镜人物（陆寻、周野、严承、值事），一个清晨窗口布景，核心道具为凝气散青瓷瓶、两块工分牌、凭条、五块灵石和账册。群众、走廊灯和药柜属于背景陈设。人物年龄、脸、服饰色号及声音均待主创定样。

| 镜头候选 | 引用与前后状态 | 生成和验收 |
| --- | --- | --- |
| 柜外双人近景 | 陆寻、周野，两块工牌由分持到并排 | 锁定二人身高和袖口。拍手部插镜，数值后期排版。 |
| 窗口侧面 | 值事在内、陆寻在外；封口瓶由值事交给陆寻 | 固定柜高和出入手方向。结束帧作为下镜参考。 |
| 严承近景与陆寻反打 | 严承身前五石，瓶仍在陆寻手里；两句发言分轨 | 先用对白做节奏稿；单人开口镜核唇形、视线，保留对方反应。 |
| 夺瓶插镜、周野反应、严承回手 | 持瓶人改变，封口变开，余药随后回到陆寻手里 | 给交接画动作关键帧或拍自有手部参考。多手接触失败时拆成夺前、反应、夺后三镜；检查观众能否说清谁抢了谁的药。 |

建议镜头记录示例（拟生产资料，尚无图像文件）：
`DF-02 → m01.gate / 窗口交药 / 陆寻·杂役衣、值事、丹房·清晨、凝气散·封口 / 窗内向外 / 开帧：药在柜内；闭帧：药在陆寻手中 / 接 DF-03 / 候选待审`。实际入库时补各资产版本、音频区间、首尾参考图和审批人。

先做定妆和反打关键帧，再出带临时音轨的静帧粗剪；一眼能认人、听清拒绝、看懂归属才跑短视频。记录候选总数、合格镜头数、人工分钟、GPU 时间、API 支出、最终可用秒数；重做一次交药镜，验证其他镜头和对白可继续使用。第二包选择青崖左右阶，先做共用输入、两个选择结果和回到同一岩台的短样片，验证药柜存失及裴所知秘密不会串线。最后试七环或剑会的高速法术。只有三类镜头都有实测，才按去重后的实际镜头表估全篇工期。
